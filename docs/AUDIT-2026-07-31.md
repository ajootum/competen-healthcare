## 1. What was built

Two bodies of work, back to back.

**A. Shift Supervisor Workspace (SSW) completion** — five new surfaces plus a navigation engine, all lenses
over data that already existed. The recurring finding was *stores and loaders written with no page rendering
them*.

**B. Platform UI standards (PUI-001…007 + HWW-UI-002)** — a design-token system, one shared header across all
17 workspaces, a component library, a notification framework, chart primitives, and an accessibility floor.

Volume: 64 source/script files changed, ~8,400 insertions, 2 new migrations (160, 161).

## 2. Provenance and method

The code was written by an AI assistant working interactively with the project owner. Specifications arrived
as `.docx` documents with mockup images; the assistant triaged each against the existing codebase, built,
self-verified, and committed per feature.

**What that means for you as auditor:**

- Commit messages are unusually long and contain the reasoning, including *admissions of bugs the assistant
  introduced*. They are a primary source — `git log` is worth reading.
- The work is heavily self-tested (see §5) but **self-tested by the author**. A test written by the same
  agent that wrote the code shares its blind spots. Independent review is exactly what is missing.
- No human wrote or reviewed the implementation line by line before commit.

shifts its baseline. Treat a single failure as suspect before treating it as a regression; re-run it alone.
This is a real fragility in the harness, not a code defect, and it is the weakest test in the suite.

## 5. What the tests actually prove — and what they don't

The 469 checks above are **not** a substitute for a test suite in the conventional sense. Be precise about
what they are:

**They do cover:**
- Pure logic against known inputs (banding, quorum, contrast, state transitions, escalation timing).
- Live-row lifecycles against the real database, with cleanup (`xw-sweep`, `ssw-*`, `pui-notifications`).
- **Source-level invariants** — e.g. "no workspace layout renders sign-out", "no component styles text with a
  fill tone". These are greps over source, and they are the only thing preventing regression on
  cross-cutting rules.

**They do NOT cover:**
- **Any authenticated browser flow.** The assistant could not log in (it must not handle credentials), so
  every UI claim is verified at compile/gate level: `tsc`, `eslint`, and an unauthenticated `curl` returning
  307/401. **Nobody has clicked through these pages while logged in.** This is the single biggest gap.
- Visual rendering. No screenshots, no visual regression, no cross-browser check.
- Performance under load. No profiling, no query-plan analysis on the new loaders.
- Accessibility *in a real assistive technology*. The a11y harness checks that ARIA attributes and CSS rules
  exist; it has not been run through NVDA/JAWS/VoiceOver, and axe/Lighthouse have not been run.
- Multi-tenant behaviour at scale. Tenant isolation is asserted for the specific paths tested, not proven
  globally.

## 6. Bugs found during the work

Listed because they are evidence about *both* the method and the codebase. Several were pre-existing; several
were introduced by the assistant and caught by its own tests.

**Pre-existing, found and fixed:**

1. **`ops-command.ts` selected `op_escalations.reason`** — the column is `summary`. PostgREST errored, a
   fail-soft `catch` swallowed it, and the Unit Manager dashboard reported **zero escalations, permanently**.
2. **Same file selected `op_safety_alerts.message`** — the column is `note`, and `active` was never selected.
   Same silent zero.
3. **Same file filtered escalations by `status !== "closed"`** — `"closed"` is not in the enum
   (`open|acknowledged|resolved|cancelled`), so the filter excluded nothing and resolved escalations counted
   as open.
   *All three corrupted the unit health score, which subtracts per incident and per escalation.*
4. **`/supervisor/analytics` was a dead link** falling through to a placeholder that told supervisors the
   analytics they used daily was "a later phase".
5. **16 real pages had no navigation entry**, including a nine-page Handover Centre sub-tree.
6. **`ops-performance.ts`** was dead code with zero importers (removed).
7. **The dashboard's "Search anything…" box had no handler** — decorative UI (removed).

**Introduced by the assistant, caught by its own harness:**

8. `resolveChannels` skipped quiet-hours suppression for critical alerts, then applied the channel-preference
   filter anyway — **a user with SMS disabled would have silenced a critical alert.**
9. Keyboard shortcuts were documented on a Help page before anything bound them.
10. A `Donut` mutated an accumulator during render (violates `react-hooks/immutability`).

**Worth your attention:** items 1–3 are the same defect class — *schema drift silently swallowed by a
fail-soft catch*. The pattern `.then(r => r, () => ({data: []}))` is used widely in this codebase. **Grep for
it and check the column names in each.** That is probably the highest-yield thing you can do:

```bash
grep -rn "() => ({ data: \[\] })" src/lib | head -40
```

## 7. Where I would be sceptical if I were you

Ranked by what I consider the real risk.

1. **Nobody has used this while logged in.** Everything is inferred from types, lints and gate codes. Sit
   down with a real account per role and click every new surface. Expect to find things.
2. **The `xw-uplift` harness is flaky** (§3). Do not trust a single green run of it.
3. **Category inference for 242 notification types.** `categoryOfType()` in
   `src/lib/notifications/framework.ts` maps legacy type strings to categories by regex. It is deliberately
   conservative — unknown types become `information` — but **a genuinely urgent legacy type that doesn't match
   a pattern will be under-prioritised.** Nothing enumerates all 242 against their intended category. If any
   type carries clinical urgency, its call site should pass `category` explicitly.
4. **`clampPriority` can only raise, never lower.** If a call site over-declares severity, nothing catches it,
   and PUI-006 makes critical alerts persistent and unsilenceable. Alert fatigue is the failure mode.
5. **The design tokens don't restyle existing pages.** ~400 pages still use hand-written Tailwind. The tokens,
   components and charts are the foundation for *new* work. Do not assume the platform looks consistent
   because a token system exists.
6. **Dark mode is not wired.** Tokens define a palette; light is the only implemented theme.
7. **The header rollout was a codemod** across 15 layouts, plus three guarded cleanup passes for orphaned
   symbols. `tsc`, `eslint` and the harness all pass, but **read `git show f053146` and check the diffs look
   sane** — a codemod that compiles is not necessarily a codemod that is right.
8. **`notify()` fallback path.** If migration 161 were ever rolled back, `notify()` silently degrades to the
   legacy column set. That is deliberate (a notification should not be lost to an unapplied migration) but it
   means a schema problem would be invisible rather than loud.
9. **Fail-soft everywhere.** Loaders return empty rather than throwing. Good for uptime, bad for detection —
   see items 1–3.

## 9. Architectural invariants

Rules the code depends on. Breaking one is a regression even if it compiles.

1. **One source per value.** `src/lib/design/tokens.ts` is the only place a design value is written;
   `globals.css` custom properties are *generated* by `scripts/gen-design-tokens.ts`. Never hand-edit the
   generated block.
2. **Clinical bands come from the engine.** Display components call `classifyPews` / `levelFromBands` — the
   same functions the write path uses. A component with its own thresholds would silently disagree with the
   record.
3. **Status is never colour alone.** Every status component renders a label or icon; there is no prop to
   suppress it.
4. **Fill vs text.** PUI-001's specified semantic colours fail WCAG as text (`warning` #F59E0B is 2.15:1 on
   white). The specified values are **fills**; `color.semanticText` carries words. The harness asserts fills
   still equal the spec *by literal hex*.
5. **Not-measured is not zero.** Null renders "not assessed" / "not measured" / an em-dash — never `0`. Chart
   gaps break the line rather than interpolating.
6. **Responsibility moves only on explicit acceptance** (WARD-003). The previous nurse stays accountable
   through the pending window; the previous active primary ends *exactly* at acceptance.
7. **A critical alert is never silenced** — not by quiet hours, muted category, min-priority filter, or a
   disabled channel.
8. **Subject-scoped writes.** Tenant scoping comes from the subject row (patient/meeting), never the caller —
   see `subjectHospital()` in `src/lib/api-auth.ts`. A super-admin acting on a tenant's data must write into
   that tenant.
